# Multi-Project Runtime

Status: design, not implemented.

Turn agent-mesh from a one-mesh-per-process runtime into a host that supervises many
projects concurrently — IntelliJ multi-project / Chrome multi-tab model.

## Decisions

| Question | Decision | Note |
| --- | --- | --- |
| Isolation | **Child process per project.** Host is a reverse proxy + event multiplexer. | Overrides the earlier in-process call; rationale below. |
| Project identity | `project.id` slug declared in `mesh.yaml`, generated by `mesh init`. | Unchanged. |
| Concurrency | Unlimited project count. Per-child memory caps enforced; global spend ceiling default-on and high. | Refined from "unbounded". |

## Why child processes

The earlier design chose in-process because the survey found zero module-scope
singletons, so N `MeshInstance`s coexist trivially. That is true and irrelevant to
the actual failure modes.

**Fault containment.** Node 20 defaults `unhandledRejection` to throw. One project's
scheduler rejecting terminates the host and every open tab with it. In-process, host
reliability equals the reliability of the flakiest project. A tool that stays open all
day cannot be built that way.

**The cost of isolation was overestimated.** It appeared to require an IPC protocol and
SSE proxying. It requires neither:

- The child is an **unmodified `mesh-server`** on a loopback ephemeral port. All ~54
  request/response routes are proxied verbatim — no route table changes, and the
  `createHttpServer` → `createMeshRouter` refactor is dropped entirely.
- The host subscribes **server-side** to each child's existing `/events/stream`. The
  ~6-connections-per-origin cap is a browser limit and does not apply to Node. The host
  fans in N streams and fans out one tagged stream to the browser.

**What isolation buys that in-process cannot:**

- Per-project memory ceiling via `--max-old-space-size` on the child
- Kill or restart a runaway project without touching the others
- One process owns one state dir — the single-writer guarantee below becomes enforceable
- Per-project CPU/RSS attribution in the UI
- A crashed project degrades to one tab showing an error, with a restart button

**Precedent in-repo:** `packages/runtime-opencode` already spawns and supervises children
(`src/index.ts:431` spawn, `:585` `killPidWithEscalation`, `:614` orphan sweep). Process
supervision is existing competence here, not new machinery.

**Accepted costs:** ~40MB RSS floor per open project; one localhost HTTP hop (~0.2ms)
per request; child lifecycle and zombie handling. All bounded and worth it.

## Correctness prerequisites

These are not multi-project features. They are existing gaps that multi-project turns
from theoretical into likely. They ship first.

### P1 — Single-writer lock on the state dir

`packages/event-store/src/index.ts:109` serializes appends with an in-process promise
chain. There is no cross-process lock anywhere in `event-store` or `persistence`
(confirmed: zero matches for lock/flock/lockfile/pidfile). Two processes appending to the
same `events.jsonl` interleave partial lines and corrupt the log. In an event-sourced
system with no ORM and no other source of truth, that is unrecoverable.

Multi-project makes this reachable: a registry entry plus a stray `mesh run` on the same
folder is enough.

Required: an exclusive advisory lock acquired on `<stateDir>` at mesh boot, holding
`{ pid, host, projectId, startedAt }`, released on clean shutdown. Stale locks whose PID
is dead are reclaimed. A live lock fails boot with a clear message naming the holding PID.
This applies to `mesh run` too, not only the host.

### P2 — Snapshot on shutdown

`MeshInstance.close()` (`apps/mesh-server/src/index.ts:381`) flushes and closes the index
and calls `supervisor.shutdown()`, but never snapshots. `maybeSnapshot()`
(`packages/core/src/kernel.ts:158`) only fires every N events (default 200) inside
`applyAndAppend()` (`:105`). Every restart replays up to 200 events per project, and
closing a tab is now a routine operation rather than a rare one.

Required: force a snapshot in `close()` before the store closes.

### P3 — Crash-safe append

Confirm `JsonlEventStore` appends are atomic per line and that a torn trailing line from
SIGKILL is detected and truncated on replay rather than aborting it. Child processes make
hard kills routine.

## 1. Project identity

Added to `schemas/mesh.schema.json` and the `protocol` types — changed together, per
AGENTS.md.

```yaml
project:
  id: payment-api            # ^[a-z0-9][a-z0-9-]{1,62}$
  name: Payment API          # optional display name
```

- `mesh init` generates `id` from the directory name, deduped against the registry.
- Migration: a `mesh.yaml` without `project.id` is accepted; the loader derives a slug
  from the folder name and warns. No hard break.
- Git-committable and stable across folder moves and clones.
- **Clone collision:** two folders may legitimately declare the same id. Identity is the
  id, so the registry rejects the second `add` and requires an explicit rename or a
  local override in the registry entry. It must never silently coexist — two entries with
  one id means two tabs racing for one lock.
- The registry also keeps a realpath → id index so re-adding an existing folder is a
  no-op focus rather than a duplicate.
- Event logs stay **per project**. There is no cross-project log.

## 2. `packages/projects` (new)

```ts
export type ProjectRef = {
  id: string;
  name: string;
  root: string;        // absolute, realpath'd
  configPath: string;
  addedAt: string;
  lastOpenedAt?: string;
};

export type ProjectStatus =
  | 'closed' | 'booting' | 'open'
  | 'crashed'    // child exited unexpectedly, restartable
  | 'locked'     // state dir held by another process
  | 'error';     // config invalid or path missing

export type ProjectHandle = {
  ref: ProjectRef;
  status: ProjectStatus;
  endpoint?: { port: number; token: string };
  pid?: number;
  health?: { rss: number; lastHeartbeat: string; restarts: number };
  error?: { reason: string; detail?: string };
};

export interface ProjectRegistry {
  list(): ProjectRef[];
  add(root: string): Promise<ProjectRef>;
  remove(id: string): Promise<void>;      // closes first; never deletes user files
  open(id: string): Promise<ProjectHandle>;
  close(id: string): Promise<void>;
  restart(id: string): Promise<ProjectHandle>;
  get(id: string): ProjectHandle | undefined;
  openIds(): string[];
}
```

**Registry file:** `~/.agent-mesh/projects.json`, override via `MESH_HOME`. Pointer list
only — no mesh state ever lives here. Writes are atomic (temp file + rename); concurrent
hosts must not shred it.

```json
{ "version": 1, "projects": [ { "id": "...", "root": "...", "addedAt": "..." } ] }
```

**Stale entries:** a missing `configPath` at `open()` yields `status: 'error'` with reason
`missing`. The entry is kept so the user can re-point or remove it. Never silently dropped.

**Lifecycle:** `add` does not boot. `open` spawns the child and waits for its `/health`.
`close` sends SIGTERM, waits for the child's own clean shutdown (which snapshots per P2
and releases the lock per P1), then escalates to SIGKILL on timeout.

## 3. Supervision

The host owns a supervision tree. Semantics mirror `runtime-opencode`'s existing child
handling rather than inventing a second style.

- **Restart policy:** exponential backoff (1s, 2s, 4s, 8s, capped 30s). More than 3 crashes
  in 60s trips a crash-loop breaker → `status: 'crashed'`, no further auto-restart, UI
  offers manual retry. Silent restart loops are worse than a visible dead tab.
- **Health:** child heartbeats to the host; a missed heartbeat window marks it unhealthy
  and triggers the restart path. RSS is reported for the tab indicator.
- **Orphan sweep:** pidfiles under `<stateDir>`, reaped on host start, mirroring
  `runtime-opencode/src/index.ts:614`. A host killed with SIGKILL must not strand children.
- **Shutdown:** host SIGTERM closes all children in parallel with a deadline, then exits.
- **Restart preserves nothing in memory** — that is the point of event sourcing. The child
  replays from its last snapshot.

Children are spawned with `--max-old-space-size` from `host.project_memory_mb`.

## 4. Host server

New entrypoint. `mesh run <mesh.yaml>` keeps the existing single-process path unchanged,
so current behavior and tests stay green.

```
/api/projects              GET     list with status + health
/api/projects              POST    add { root }
/api/projects/:id/open     POST
/api/projects/:id/close    POST
/api/projects/:id/restart  POST
/api/projects/:id          DELETE
/api/p/:projectId/<rest>   *       reverse proxy to child, path preserved
/api/events/stream         GET     multiplexed browser stream
```

- Unknown or closed `projectId` → **409** with `{ status }`, not 404. The dashboard uses
  this to offer "open project".
- Proxy is transparent: method, headers, body, status, streaming response bodies.
  `/artifacts/:id/content` and `/workspace/run` must stream, not buffer.
- Legacy bare routes (`/status`, `/events/stream`) proxy to the single open project when
  exactly one is open, else 409 ambiguous. Keeps existing CLI and scripts working.
- The dashboard SPA is served by the host, never by children.

**Security.** Children bind to `127.0.0.1` on an ephemeral port and must never be
reachable off-host. Each child is spawned with a per-child bearer token that the host
injects on every proxied request; the child rejects unauthenticated requests. Without
this, any local process can drive a child directly and bypass the host entirely — which
matters because these children execute agent-authored code and shell commands. The token
is passed via the child's environment, not argv, so it does not appear in `ps` output.

## 5. Event multiplexing

The host holds one server-side subscription per open child (`/events/stream`) and exposes
one browser-facing stream. `MultiplexHub` lives in `packages/observability`; per-project
`SseHub` (`src/sse.ts:4`) is untouched inside each child.

```
GET /api/events/stream?projects=a,b,c&since=a:120,b:44
```

```json
{ "projectId": "a", "seq": 121, "event": { ... } }
```

- Resume cursors are **per project** — sequence numbers are per-project logs.
- Opening a project must not drop the browser connection. Reconnect with the full project
  set and per-project cursors; the cursors make it lossless and it is far less code than a
  mutable-subscription side-channel.
- `turn.token` streaming frames (`store.tsx:419`) carry `projectId` too.
- Backpressure: a slow browser must not stall the host's ingestion from children. Bound
  the per-client outbound queue and drop to a resync signal on overflow rather than
  growing without limit.

## 6. Dashboard

```
<ProjectsProvider>                                    // registry, tabs, one SSE connection
  <MeshProvider key={projectId} projectId={...} />     // one per open project
```

- `MeshProvider` (`store.tsx:180`) gains a `projectId` prop. Its 30+ field `MeshState`
  needs **no** project dimension — each project gets its own provider instance. Do not add
  a project map inside `MeshState`.
- Hash gains one segment: `#/p/:projectId/steps/step/turn-ab12`. Update `parseHash`
  (`:109`), `hashFor` (`:120`), `setView` (`:233`). Bare `#/steps` redirects to the active
  project. Deep links must survive reload, including into a not-yet-open project — which
  opens it.
- `api.ts:44` `api()` takes `projectId` and prefixes `/api/p/:id`. Bare form kept for
  registry calls.
- SSE moves from `MeshProvider` up into `ProjectsProvider`; frames route by `projectId`.
  `connectSse()` (`:385`) and its 3-failure reconnect (`:404`) move with it.
- Background tabs keep state and stop rendering, but keep ingesting so switching back is
  instant. Retained events per background project are capped, refilling from `/events` on
  focus — otherwise ten idle tabs are an unbounded memory leak in the browser.
- Tab bar: add via folder picker, close, reorder, per-tab status (running / parked /
  crashed / locked) and RSS. A crashed tab shows the exit reason and a restart button.

## 7. Resource policy

Unlimited project count — process isolation makes that structurally safe, so an arbitrary
cap would be nannying. What replaces the cap is real enforcement:

`~/.agent-mesh/host.yaml`, beside `projects.json` — **not** a block in any project's
`mesh.yaml`. Every knob here is cross-project, and an aggregate ceiling declared by one
project would be one of N conflicting ceilings with no principled winner. The file is
optional; absent or malformed, it resolves to these defaults with a warning.

```yaml
host:
  project_memory_mb: 512        # per-child --max-old-space-size
  max_concurrent_turns: null    # null = unlimited
  spend_ceiling_usd: 50         # aggregate across open projects; null disables
  model_prices:                 # USD per million tokens
    anthropic/claude-sonnet-4: { input_per_mtok: 3, output_per_mtok: 15 }
  default_usd_per_mtok: 3       # unpriced models bill here, never at zero
```

- Memory is enforced per child by the runtime itself. An OOM kills one project, and the
  supervisor surfaces it as a crashed tab.
- `/api/projects` reports aggregate live cost across open projects, so total spend is
  always visible rather than inferred from N separate budget views.
- **Cost is measured in tokens and priced host-side.** The kernel has no notion of money
  and should not gain one — a child must not know what its operator pays. Children report
  cumulative billed tokens per model on the heartbeat that already carries RSS; the host
  multiplies by `model_prices`. Cumulative, not deltas, so a dropped line cannot silently
  shrink the total. A model with no price bills at `default_usd_per_mtok` rather than zero:
  an unpriced model billing at zero would be an invisible way to spend past the ceiling,
  which is the one failure a backstop cannot have.
- The spend ceiling defaults **on** at a high value. Per-mesh budgets in `packages/core`
  are unchanged and still authoritative within a project; this is only the cross-project
  backstop. N projects × per-mesh budget otherwise has no ceiling at all, and each running
  project spawns its own `runtime-opencode` children. One line disables it.
- **Both aggregate limits park, they do not kill,** and both act after the fact. Parking
  keeps the state dir, event log and lock, so raising the ceiling resumes a mission instead
  of replaying it. Enforcement is after-the-fact because intercepting a turn would need an
  IPC lease protocol; inventing one to gain seconds of precision on a backstop is not worth
  the machinery. The ceiling parks *every* open project — it is a total, so any project
  left live keeps pushing an already-breached number up. `max_concurrent_turns` parks
  newest-first and only until the total fits.
- Enforcement runs on each heartbeat and on each `/api/projects` poll. Neither adds a timer
  to the host: the beat already exists, is already `unref`'d, and is already cleared on
  shutdown, so nothing here can outlive `close()`.

- `tests/event-store/state-lock.test.ts` — second open fails; stale lock with a dead PID is
  reclaimed; lock released on clean and unclean exit
- `tests/event-store/torn-line.test.ts` — replay tolerates a truncated trailing line
- `tests/core/snapshot-on-close.test.ts` — `close()` snapshots; restart does not re-replay
- `tests/projects/registry.test.ts` — add/open/close/remove, duplicate id, clone collision,
  stale path, `MESH_HOME` override, concurrent atomic writes
- `tests/projects/supervision.test.ts` — child crash restarts with backoff; crash loop trips
  the breaker; host SIGKILL leaves no orphans
- `tests/projects/isolation.test.ts` — two projects open; one killed mid-mission leaves the
  other running and its log intact
- `tests/server/host-routing.test.ts` — proxy fidelity incl. streaming bodies, 409 on closed
  project, legacy fallthrough with one vs many open, token rejection
- `tests/observability/multiplex.test.ts` — per-project resume cursors, lossless reconnect
  across an open, frame tagging, slow-consumer backpressure

## Explicitly out of scope

- Cross-project event log or unified timeline
- Sharing artifacts or agents between projects
- Remote/hosted projects — the registry holds local paths only
- Multi-user auth; the per-child token is process isolation, not user identity
